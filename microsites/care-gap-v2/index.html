Status: brainstorming only. Nothing built. If it goes ahead, step 1 is a short spec to review.


1. Every format is the same thing underneath


Backgrounds, text boxes placed on them, and timing. Only the counts and the clock differ.


BackgroundsText boxesTiming


Single post13 (headline, accent, body)static


Single post carousel6-9, one per slide3, by format (Cover / Text / End)static, one frame per slide


YT Titlesper section, or pictures within itsection title + captionstitle lasts its section; captions per spoken phrase


YT Interviewpresenter scene + picturestitle, card, Q: line, captions, ask pillscard per chapter; captions and pills timed to the voice


2. One engine


    

  • One composition format: a list of frames. Each frame = a background + text boxes. Each box = role, text, position, style, start/end time. A still = a frame with no time.
    • 

  • The methods become presets that write that format (single post = 1 frame, carousel = N frames, Titles / Interview = timed frames).
    • 

  • One editor: frames along the bottom, boxes on the canvas, the shared Typography panel, plus a timeline for videos to drag each box's start/end (per-box durations).
    • 

  • Two outputs from one file: PNGs (browser) and MP4 (Python renderer).
    • 

  • Timing can follow the voice: "show while these words are spoken", so edits keep their timing.
    • 

  • Formats become reusable looks (Cover / Text / End, section title, chapter card) any method can borrow.
    • 



3. One long-form script feeds every method


    

  • Whole script = longform video. Sections = carousel slides. Strongest lines = single posts. One section = a Reel. Prose = blog + email. Hook + titles = YouTube packaging.
    • 

  • Outputs are cuts of the same material, not new generations, so message and voice stay consistent.
    • 

  • Example: Dualities (25 sections) = 1 longform, ~5 carousels, 25 posts, a Reel series.
    • 



4. Clipping long-form into Reels / Shorts


    

  • A clip = a time range in the composition, re-laid out 9:16.
    • 

  • Needs: start/end (15-60s), stands alone, a new 1-2s hook line, vertical layout (captions up, bigger text, section title as a banner), an end beat.
    • 

  • AI suggests ranges scored on hook strength, standalone clarity, payoff and length; you approve or trim on the timeline.
    • 

  • Script structure already marks most cuts: each Titles section / Interview chapter is a natural clip.
    • 



5. One generation, disseminated


    

  • One idea, one script, one approval, many assets, published over time (pairs with the Buffer queue).
    • 

  • Approve at the source: a fix in the script fixes every output.
    • 

  • Each method keeps its own rules (platform, format, length): adapting, not copying.
    • 

  • You choose which outputs to make; text cuts are cheap, renders are made in waves for what you'll publish.
    • 



6. It all lives in the pillar


Write the pillar to a structure every format can cut from:


Pillar partUsed by


Hook (2-4 spoken sentences)video opening, Reel hooks, carousel cover, headlines


Titled sections (2-6 word title + narration)Titles video, carousel Text slides, Reel clips, blog H2s


One quotable line per section (setup + payoff)single posts, carousel headlines, thumbnail text


Proof per section (number, story, example)post bodies, carousel "why", blog depth


Visual note per sectionbackgrounds, video pictures, carousel visual thread


Payoff + call to actionEnd slides, video outro, email close


Questions it answersInterview episodes, SEO/blog angles, FAQ


Note: the pillar's structure is defined in the Information Flow Contract. Changing it needs your explicit yes on the exact wording first.


Possible build order (if it goes ahead)


    

  1. Composition format + the four methods also saving into it (nothing else changes).
    2. 

  2. One editor: posts and carousels first, then videos with the per-box timeline.
    3. 

  3. Video renderer draws from the composition (per-box durations in the final video). Riskiest step.
    4. 

  4. Structured pillar + "make outputs from this pillar" + clip suggestions.
    5. 

  5. Retire the old separate editors.
